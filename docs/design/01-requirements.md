## 2. システム概要

### 2.1 背景

日本の贈答文化では、商品に**熨斗（のし）**を掛けて贈るのが一般的な商習慣である。
熨斗には次の指定要素がある。

- **表書き** … 熨斗の上段に印字する文言（御中元・御歳暮・御祝・内祝 など）
- **名入れ** … 熨斗の下段に印字する贈り主の名前
- **のしの種類** … 包装紙の外側に掛ける「外のし」／内側に掛ける「内のし」

これらは Shopify の標準機能が構造的に持たない概念である。日本の EC 事業者が Shopify を
採用する際、この領域はほぼ必ず個別対応が必要になる。

### 2.2 解決する課題（As-Is → To-Be）

Shopify 標準機能だけで熨斗に対応しようとすると、次の運用になる。

| 工程 | As-Is（標準機能のみ） | 課題 |
|---|---|---|
| 購入者の指定 | 注文メモ欄に自由記述 | 表記ゆれ・記入漏れ・そもそも記入欄の存在に気付かない |
| 料金の請求 | のし代・包装料の商品を購入者自身にカート投入させる、または後から手動請求 | 請求漏れ・二重請求・購入者が商品だけ削除できてしまう |
| 受注確認 | 注文メモを目視で読む | 複数商品のうちどれに熨斗が必要か判別できない。転記ミス |
| 出荷 | メモを手作業で転記して熨斗を作成 | 誤字・取り違え |

本アプリが実現する To-Be は次のとおり。

| 工程 | To-Be | 効果 |
|---|---|---|
| 購入者の指定 | カートページで**商品行ごと**に構造化入力（表書きはプルダウン選択） | 表記が統一される。指定漏れが起きにくい |
| 料金の請求 | 熨斗指定に応じて のし代・包装料を**自動でカートに加算** | 請求漏れが起きない。数量変更にも自動追随 |
| 受注確認 | 受注画面に熨斗情報を**カードとして整形表示** | どの商品にどの熨斗かが一目で分かる |
| 出荷 | 印字用データとして出力。誤字は受注画面から訂正 | 転記ミスを減らす |

### 2.3 対象範囲

架空の日本茶 D2C ブランド `chanoka` のデモストア（Shopify 開発ストア `chanoka-demo`）に
インストールして動作させる。テーマは Shopify 標準テーマ Dawn をベースとする。

## 3. 利用者と役割

| 利用者 | 役割 | 主な操作場所 |
|---|---|---|
| **購入者** | 商品に掛ける熨斗を指定する | ストアフロントのカートページ |
| **マーチャント（店舗運営者）** | 表書きの選択肢、のし代・包装料の金額、包装料無料のしきい値を管理する | Shopify 管理画面 |
| **出荷担当** | 受注内容から熨斗の印字内容を確認し、必要なら訂正する | Shopify 管理画面の注文詳細ページ |

## 4. 機能要件

優先度: **必須** = これがないと業務が回らない / **推奨** = 実用性を大きく高める。
フェーズ: 1 = コア機能（これだけで作品として成立）/ 2 = 説得力の上乗せ。

### 4.1 購入者向け機能

| ID | 機能 | 内容 | 優先度 | フェーズ |
|---|---|---|---|---|
| FR-01 | 熨斗の要否指定 | カート内の**商品行ごと**に熨斗の要否を指定できる。同一カート内で「この茶葉は熨斗あり、こちらはなし」が成立する | 必須 | 1 |
| FR-02 | 表書きの選択 | マーチャントが登録した選択肢から表書きを選ぶ。自由記述にはしない | 必須 | 1 |
| FR-03 | 名入れの入力 | 熨斗に印字する贈り主の名前を入力する。任意項目 | 必須 | 1 |
| FR-04 | のしの種類の選択 | 外のし／内のし を選ぶ。既定は外のし | 必須 | 1 |
| FR-05 | 指定内容の保持 | 指定した熨斗情報がカートから注文まで引き継がれる | 必須 | 1 |
| FR-06 | 熨斗指定の変更・解除 | カート上で後から表書きの変更や熨斗の取り消しができる | 必須 | 1 |
| FR-16 | 購入後の内容確認 | 注文完了後、指定した贈答内容を購入者が確認できる | 推奨 | 2 |

**FR-01 の指定単位について**: 熨斗の指定単位は「注文単位」ではなく「商品行単位」とする。
実務では 1 回の注文で複数の贈り先に別々の熨斗を掛けるケースが発生するため。
なお同一行内の複数数量には**同じ熨斗**が適用される（別の熨斗を掛けたい場合は、
商品ページから別途カート投入すれば属性が異なるため別行になる）。

### 4.2 料金計算機能

| ID | 機能 | 内容 | 優先度 | フェーズ |
|---|---|---|---|---|
| FR-07 | のし代の加算 | 熨斗を指定した行に対し、のし代を数量分加算する | 必須 | 1 |
| FR-08 | 包装料の加算 | 熨斗を指定した行に対し、包装料を数量分加算する | 必須 | 1 |
| FR-09 | 料金の取り消し | 熨斗を解除した場合、対応する のし代・包装料を取り消す | 必須 | 1 |
| FR-10 | 数量変更への追随 | 商品の数量を変更した場合、のし代・包装料の数量も追随する | 必須 | 1 |
| FR-11 | 料金行の保護 | 購入者が のし代・包装料だけを削除できないようにする。親商品を削除した場合は対応する料金も消える | 必須 | 1 |
| FR-12 | 包装料の無料化 | 小計が一定金額以上の場合、包装料を無料にする。**のし代は無料化の対象外** | 推奨 | 2 |

**FR-12 の対象範囲について**: 当初「のし・包装料を無料」と定義していたが、
のし代は熨斗そのものの対価であり無料化すると「熨斗を掛ける理由」が値引き目的にすり替わる。
包装料のみを対象とする。

### 4.3 マーチャント向け機能

| ID | 機能 | 内容 | 優先度 | フェーズ |
|---|---|---|---|---|
| FR-13 | 表書きマスタの管理 | 表書きの選択肢を管理画面から追加・編集・削除・並べ替えできる。**選択肢をコードに持たない** | 必須 | 1 |
| FR-14 | 料金設定の管理 | のし代・包装料の金額、包装料無料のしきい値を設定できる | 必須 | 1 |

### 4.4 受注業務向け機能

| ID | 機能 | 内容 | 優先度 | フェーズ |
|---|---|---|---|---|
| FR-15 | 受注画面での熨斗確認 | 注文詳細ページに、どの商品にどの熨斗を掛けるかをカードとして常時表示する | 必須 | 1 |
| FR-17 | 印字用データの出力 | 熨斗の印字内容を一覧・コピーできる形で出力する | 推奨 | 2 |
| FR-18 | 受注後の訂正 | 表書きの誤字などを出荷担当が訂正できる。**購入者が入力した元の値が失われず、訂正後の値と併せて確認できる** | 推奨 | 2 |

**FR-18 の実現方式の制約**: 注文確定後の商品行の属性は Shopify の仕様上変更できない
（CON-05 参照）。訂正値は別データとして保持し、元の入力値と併記する方式とする。

**保持する世代について**: 本要件が求めるのは「元の入力値が失われないこと」であり、
全訂正の履歴を残すことではない。採用方式では「元の入力値」と「最新の訂正値」の
2 世代が保持される（[詳細設計書](./03-detailed-design.md) の5.3節参照）。

## 5. 非機能要件

| ID | 分類 | 要件 | 判定基準 |
|---|---|---|---|
| NFR-01 | 保守性 | **ストアのテーマファイルを一切改変しない**。機能はアプリ拡張のみで足す | ① テーマの差分が 0 であること（設置用の `templates/cart.json` へのブロック追加を除く）／② **テーマの実装詳細に依存している箇所が設計書に列挙されていること**（CON-08） |
| NFR-02 | 運用性 | 開発者側のサーバー・データベースを持たない。恒久的な運用費が発生しない | 月額費用 0 円で動作し続けること |
| NFR-03 | 保守性 | 金額に関わる設定値（variant ID・しきい値）を**単一の場所**で管理する | 片方だけ修正して金額がずれる事故が構造的に起きないこと |
| NFR-04 | 信頼性 | 設定値が未投入・破損している場合、カートを止めずに料金加算のみ行わない（フェイルセーフ） | 設定欠損時も購入導線が機能すること |
| NFR-05 | 信頼性 | 料金行と商品行の対応関係が崩れた場合、次のカート操作時に自動的に整合する | 孤児となった料金行が残り続けないこと |
| NFR-06 | 品質 | 金額を動かすロジックは自動テストで担保する。目視確認のみで完了としない | fixture ベースの単体テストが CI で実行可能であること |
| NFR-07 | 法令対応 | 軽減税率に対応する。飲食料品は 8%、のし代・包装料は 10% として計算する | 実機のチェックアウトで、1 注文に 2 つの税率が混在した状態の税額が正しいこと。**かつ包装料の割引が他の税区分に按分されないこと**（通し確認の項目 9 で確認する。自動テストは税を検証していないため、実機確認が唯一の担保となる） |
| NFR-08 | 国際化 | 画面文言を日本語・英語で切り替えられる。ただし**データとして保存する値は翻訳しない** | 言語切替後も保存済みの熨斗情報が一致すること |
| NFR-09 | セキュリティ | アプリに付与する権限は必要最小限とする | 使用していないスコープを保持しないこと |
| NFR-10 | 性能 | カートページの操作に対し、体感で待たされない応答を返す | 熨斗の保存操作が、**押下からページの再読み込み完了までを含めて**数秒以内に終わること（保存は必ず再読み込みを伴う設計のため、通信のみの時間では判定しない） |

**NFR-08 の補足**: 「外のし」「内のし」などデータとして保存する値を翻訳対象にすると、
言語を切り替えた際に保存済みの値と一致しなくなり、受注側が読む印字用データの表記も揺れる。
**翻訳するのは画面に表示するラベルのみ**とする。

## 6. 制約条件

| ID | 制約 | 影響 |
|---|---|---|
| CON-01 | チェックアウト内（情報・配送・支払いステップ）への UI 追加は Shopify Plus 限定 | 熨斗の入力 UI は**カートページに置く**。チェックアウト内には置けない |
| CON-02 | extension-only アプリは custom distribution 限定で、App Store 公開ができない | 配布形態を custom distribution とする |
| CON-03 | 標準テーマ Dawn のカート商品セクションは、アプリのブロックを受け付けない | 入力 UI は**カートのフッター**に 1 ブロック置き、その中に行ごとの入力を並べる。商品行の中には差し込めない |
| CON-04 | ストアフロントから料金商品をカートに追加するには、その商品が販売チャネルに公開されている必要がある | のし代・包装料のダミー商品をオンラインストアに公開する |
| CON-05 | 注文確定後、商品行の属性（line item properties）を変更する API が存在しない | 受注後の訂正は別データとして保持する（FR-18） |
| CON-06 | 購入完了ページ（Checkout UI Extension）の拡張は、**注文データをほとんど参照できない**。参照できるのは「初回注文か否か」と「注文番号」程度で、商品行の属性（＝熨斗情報）は取得できない。かつ管理系 API へ直接アクセスする手段もない | **解決済み（2026-08-15）**。購入完了ページでの実現は諦め、Customer Account UI Extension（注文ステータスページ）に実現方式を変更した。このAPIは注文の line item の`attributes`（line item properties相当）を直接返すため、CON-06の制約自体を回避できる |
| CON-07 | 第 1 弾ポートフォリオの公開テーマを改変しない | 検証は複製した非公開テーマ上で行う |
| CON-08 | テーマファイルは改変しないが、**Dawn の実装詳細に依存している**。①カート商品行の ID 命名規則、②先頭が `_` の属性を画面に表示しない実装、の 2 点 | **対象テーマを Dawn に限定する**。他テーマや Dawn の大幅な改版では動作しない可能性がある。依存箇所は[詳細設計書](./03-detailed-design.md)に列挙し、テーマ更新時の確認対象とする |

## 7. スコープ外

次の要件は本アプリでは扱わない。必要性が生じた時点で再検討する。

- 配送希望日時の指定
- メッセージカードの文面入力
- 納品書の金額非表示（贈答時の「お値段を伏せる」対応）
- **複数配送先への別送**（贈り先ごとに配送先を分ける）
- App Store への申請・審査対応

**別送をスコープ外とする影響**: 別送に対応する場合、熨斗の指定単位を「商品行」から
「数量 1 単位」へ変更する必要がある（FR-01 の設計が変わる）。現時点では商品行単位で
問題が生じないことを確認しているが、将来別送を実装する際は指定単位の再設計が前提となる。

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| 熨斗（のし） | 贈答品に掛ける紙。表書きと名入れを印字する |
| 表書き | 熨斗の上段に印字する文言。贈る目的を表す（御中元・御歳暮・御祝 など） |
| 名入れ | 熨斗の下段に印字する贈り主の名前 |
| 外のし | 包装紙の**外側**に熨斗を掛ける方式。贈答の目的が一目で分かる |
| 内のし | 包装紙の**内側**に熨斗を掛ける方式。控えめな贈り方とされる |
| のし代 | 熨斗の作成・印字に対する料金 |
| 包装料 | 贈答用包装に対する料金 |
| 商品行（カート行） | カート内の 1 明細。同一商品でも属性が異なれば別行になる |
| 料金行 | のし代・包装料として自動追加されるカート行の呼称（本設計固有の用語） |
| 軽減税率 | 飲食料品等に適用される 8% の消費税率。標準税率は 10% |
